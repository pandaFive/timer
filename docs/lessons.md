# Lessons - 過去の失敗と学び

## 記録ルール

- バグを解決したら、ここにパターンと対策を追記する
- 設計上の判断ミスや整合性の注意点も記録する
- 同じ失敗を繰り返さないための知見をまとめる

## 2026-02-13

- プリセット保存とフォーム復元を同じキーで管理すると責務が混ざるため、`draft`（自動保存）と `presets`（明示保存）を分離した方が安全
- 永続化仕様の変更時は、旧キーからの互換移行（初回のみ）を実装しないと既存ユーザーの設定が失われる
- `onPhaseChange` の引数が `round` のみだと、セット間休憩判定を呼び出し側で推論する必要があり脆弱になる
- 遷移通知は `phase/set/round` を明示的に渡し、判定ロジックを推論ではなく事実ベースで記述する
- 音声案内とカウントダウンが連続する短フェーズでは、共通 `cancel()` による相互干渉を避ける設計が必要
- `speechSynthesis.speak()` は失敗時に呼び出し元処理を巻き込まないよう `onerror` と `try-catch` の両面で防御する
- 入力フィールドの順序要件は見た目変更だけでなく、DOM順序を検証する回帰テストを追加して固定する
